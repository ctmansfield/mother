## Walkthrough and acceptance

Run from the exact documented code roots, with PATH/interpreter and operator context recorded. Any variant that differs from steps below must have a source pin and executable recipe in the manifest. No inherited undocumented shortcut. Record each attempt, exit status and evidence digest. If missing dependencies or unsafe target readback prevent a step, stop at the last safe boundary, document it and rerun that boundary after review.

1. **Preflight, define and boot without a NIC.** Use the pinned fresh-target clone helper's documented `preflight` then `define` invocation with selected cold seed/hash, host/boot, target UUID/MAC and the fresh-target names. Confirm all target resources absent before definition; never overwrite or reuse an intent, existing disk or domain. Before `virsh --connect qemu:///system start "$domain"`, match the stopped domain/disk/readback and no NIC/shares/passthrough. Check seed and accepted clone remain unchanged. Take no action against unrelated resources.
2. **Isolated identity and network.** Over the verified exact guest agent, run `python3 -I -B guest_identity.py "$expected_seed_hostname" "$archive_hostname"` while NIC-free. Verify no inherited active SSH, unrelated credential state, phone/relay use or seeded archive state. Reboot the owned guest as documented and verify generated machine and SSH host keys, unique name and unchanged approved baseline. Use `guest_link.py "$reserved_mac" "$guest_cidr"` and the pinned fresh-target variant of `host_link.py "$private_plan"`. Record exact bridge/filter readback, no default route and no public/SQL/phone ingress. Keep temporary phone relay closed throughout.
3. **Install offline and initialize once.** Transfer wheels and r2 bundle with bounded guest-agent commands and per-file hash verification. Run pinned `python3 -I -B guest_dependencies.py wheel-pins.json "$guest_ip"`, then `python3 -I -B guest_package.py`. Read installed member/venv checks before the service step. Run pinned `python3 -I -B guest_service.py "$private_guest_config" "$client_hostname" "$guest_interface"` only on the service-owned empty root, with fresh TLS and config. This initializes PF-001 and custody once and validates the marker and schema. Record the exact startup-fix install and resulting unit/override hash. Never initialize on ordinary start or restart.
4. **Readiness and refusals.** Read back the owned listener, private mount/owner, exact config/schema/catalog and absence of wildcard/SQL/public/phone routes. Verify direct HTTPS hostname/CA and expected guest leaf; check wrong hostname, untrusted CA and plaintext fail safely. Use correct HTTPS authority or a scoped local resolver override, never `-k`. Verify existing-root init and wrong scope/version/catalog refusal via an isolated disposable negative-test root or the documented non-destructive probe. Do not alter the accepted or active reproduction stores to manufacture mismatch. Ordinary restart uses only `systemctl restart phoenix-mse-archive.service`; marker and existing identity remain identical.
5. **Synthetic data and operator roles.** See [exact endpoints and selectors](https://github.com/ctmansfield/mother/blob/86e362f04aac4431ecd637a2c5e0c1aee1f03ad5/integrations/mse_archive_service/README.md#wire-and-operator-readback). Private host test client uses `curl --fail-with-body --cacert "$trial_ca" --header @"$ingest_headers" --header 'Content-Type: application/json' --request PUT --data-binary @"$fresh_original" "$origin/v1/archive/batches/$fresh_batch"` with a finite timeout. Header files are private, one per role. For expected error statuses preserve response status/exit without printing raw content. Reopen receipt GET, repeat the exact batch, then exercise changed allowlisted bytes with the same batch ID and expect conflict. Read scoped receipt/revision/join and one authorized bounded export; wrong roles and scope selectors deny. Evidence role fetches the exact retained original. Compare artifact bytes, receipt identity, committed source/processing rows, source-only or delete state, exact value/unit and cutoff. Load the complete canonical export with `python -B -m integrations.mse_archive_service.load_export --input "$verified_export" --sha256 "$approved_response_sha256" --output "$new_copy"` and compare relational keys/rows and integrity. Verify the accepted archive's historical receipts remain outside the trial.
6. **Controlled reboot and disposition.** Record preboot host/guest pins, marker, source/member/config/leaf/link/unit digests, original/receipt, exact exported response and isolated address. Enable the pinned archive unit as documented and reboot only the disposable guest. Record boot→address→service active→authenticated HTTPS readiness using actual timestamps, and inspect the exact network readiness job. Require no generic two-minute timeout on the fixed service path, preserved isolation and exact pre/post retained data. No postboot PUT is required. Verify scoped closeout using the documented fresh-target stop and removal or retention policy for its guest/local isolated link. Recheck accepted archive direct access and closed phone relay. Preserve logs, state and failed evidence. No backup/restore or host reboot.
