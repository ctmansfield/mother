# Offline MSE integration interfaces, draft 0.2

Candidate for GADGET freeze under [revision 2](https://github.com/ctmansfield/mother/pull/23#issuecomment-7041572809). Only local synthetic exchange is in scope. [Schema](offline-integration.schema.json) gives exact members and state nullability. The rules below also apply when structural validation succeeds. [Golden vectors](golden-vectors.json) include exact source bytes and encodings.

## Encoding and clocks

- Parse UTF-8 JSON with unique keys and finite values. Keep original Swift JSON numeric tokens for value, start/end, collector receipt and deletion. Read exact decimals. Canonical decimal strings use fixed notation, remove trailing fractional zeros, and encode either zero sign as `0`. Preserve input lexemes separately. Reject out-of-range, unsupported or implausible representations at their defined boundary without overwriting evidence.
- For digest inputs, write compact sorted-key JSON in Unicode code point order, UTF-8, standard short control escapes and lowercase Unicode control escapes, with no Unicode normalization, escaped slash or trailing newline. Enforce Unicode scalar strings and safe-range integers. Floats are disallowed in derived envelopes. SHA-256 output is lowercase hex. Input bytes are independently hashed without canonicalization.
- Use canonical UTC with six fractional digits and valid Gregorian dates. Convert Swift numeric dates as seconds since 2001-01-01 UTC, rounded to nearest microsecond, ties to even. Record any precision loss per field and retain the original lexeme. Event start/end, source availability, collector receipt, MOTHER receipt and MOTHER commit are separate. Source availability is null for this capture shape, and collector receipt cannot establish source or MOTHER availability.
- Use deterministic bounded parsing. The local caller supplies positive byte, record, depth and numeric-token limits before parsing. Reject excess work as a whole, with no advanced checkpoint. No production limits are selected. JSON pointers use RFC 6901 escapes. Sort and deduplicate pointer and lexeme lists by code point order. Sort loss entries by canonical bytes and reject duplicates.

## Exact digest preimages

Each tuple below denotes a JSON array. For `H(x)` hash the canonical JSON bytes of `x`.

| Digest | Preimage |
| --- | --- |
| artifact.sha256 | Exact original captured bytes |
| anchor_sha256 entry | Exactly the decoded opaque anchor bytes |
| revision_sha256, upsert | H([`mse.source-revision/0.2`, scope, native_id, `upsert`, {channel, value, unit, start, end, source_name, bundle_id}]). The fact uses canonical decimals of **original** value and Swift start/end seconds. unit is the original unit. Collector receipt, original lexical spelling, capture locators, classifications and processing fields are excluded. |
| revision_sha256, delete | H([`mse.source-revision/0.2`, scope, native_id, `delete`, canonical decimal of original deleted-at seconds]). All original_deleted_at lexemes in one fact must resolve to the same exact decimal. |
| export_sha256 | H([`mse.export/0.2`, full export object]) |
| receipt_id | H([`mse.receipt-id/0.2`, archive_id, scope, batch_id]). This stable lookup ID excludes status, export/artifact hashes, run and clocks. It conveys no authentication. |
| processing_revision_sha256 | H([`mse.processing-revision/0.2`, revision_sha256, normalizer_version, {channel, value, unit, event_start, event_end, epistemic_type, classification_basis, classification_evidence_sha256}]) using the normalized observation fields. |

## Export and acceptance

Scope consists of synthetic subject, HealthKit source system, caller-assigned store instance, and healtharchive collection. One scoped UUID identifies the logical observation. Captures bind exact bytes separately from delivery. Sort export revisions by (native_id, operation, revision_sha256). Preserve facts only once per key and bind every original locator. For equal upsert digests within one capture, choose the sighting at the lowest **numeric** index in the original `readings` array, independent of candidate enumeration. Copy its entire observation payload, including collector receipt and all original number lexemes. Keep every original reading pointer, sorted by code point order. Preserve alternate payloads in the original artifact and report a loss with field `source_sighting`, reason `alternate_sighting_retained_in_original` and that reading pointer when an alternate payload differs. Never choose by collector clock or lexical pointer order, and never combine fields from different sightings. Reordering the original array creates different capture bytes and can change the representative without changing source fact identity. Multiple explicit deletions for one UUID retain distinct exact source times even if rounded to the same UTC time. Merge equivalent delete facts across embedded and dictionary forms. Unknown UUID deletions are valid. Absence from a partial or empty capture creates no deletion. A known delete suppresses late upserts at and after its authoritative commit cutoff. Preserve historical facts before that cutoff.

Equal source digest across captures is a repeated fact with separate custody/sighting lineage. Collector receipt drift alone does not alter source revision identity. For the first slice, unequal upsert source digests under one scoped UUID quarantine the entire conflicting batch, preserving prior accepted state. A future qualified source correction requires explicit predecessor evidence and a reviewed policy. A processing change uses a separately versioned processing revision and never asserts a source correction. Anchor hashes are scope-bound opaque evidence without ordering semantics or server checkpoint authority.

HR derivation stays unknown in native captures. Keep it in evidence and record exclusion from the reference input. Measured HR is admissible only when independent evidence is verified and its digest pinned. SDNN is vendor-derived. Retain otherwise valid finite zero and negative scalars as source-only evidence. Preserve the exact signed input lexeme, canonical signed decimal value, unit, source digest and all locators. Emit a loss with field `value`, reason `outside_reference_positive_domain` and the original value pointer. Neither zero nor negative becomes a valid normalized PF-001 observation or native MSE input. Keep the PF-001 source revision and report the exclusion at snapshot scope when the fact is otherwise eligible. Never clip, take absolute values or fabricate a substitute. A source-only omission can coexist with a normalized receipt for a valid batch whose other records were processed. Malformed numbers, nonfinite tokens and magnitudes outside the parser's declared numeric bounds fail validation. Acquisition window, calibration, permissions and source availability remain unknown in this capture format.

The original goes to a private local archive. Verify receipts against expected archive ID **and** scope from local configuration, then compare the full object to the reopened authoritative ledger record, artifact bytes and, for normalized receipts, exact PF-001 run and record bindings. A portable receipt or digest alone gives no acceptance. Scope+batch retries reuse the same receipt identity. Different artifact or export digest conflicts once bound. A previously null export digest can be bound once during valid normalization. This never changes the original artifact binding. Preserve first MOTHER receipt time. Committed time and sequence identify the reported durable stage and advance on a stage transition. Rejected requests have no commit, and conflict leaves the existing receipt and archive untouched. A quarantined state retains bytes and reason and publishes no authoritative normalized run. Prepared/uncertain journal records remain internal. A retry after terminal normalization returns the stored object exactly.

## Snapshot and reference bridge

An immutable snapshot selects observations complete within the requested half-open interval, with inclusive end completion for an interval whose start is before the end boundary, and selects their accepted state at the local commit sequence cutoff. Retain scoped delete facts committed through cutoff, including unknown UUIDs, so they do not depend on the existence of a selected upsert. Validate cutoff, chronology, interval, scope, archive, member digest and reopened receipt bindings. Sort observation and deletion arrays by (native_id, revision_sha256) and reject duplicates. Only one active source and processing revision per scoped UUID is permitted. Unknown coverage and unavailable values are explicit.

### Deterministic representative at cutoff

A snapshot request explicitly names one exact `normalizer_version`; record it in the snapshot. Use only normalized, reopened receipt-backed candidate members with commit_sequence at or below the requested cutoff. For an upsert, first establish the eligible source fact under the source conflict/deletion rules. Then select only candidates materialized using the requested normalizer. If there is no matching processing candidate, omit the observation with a typed `normalizer_unavailable` loss. If the same eligible source fact and requested version has multiple distinct processing digests, reject the snapshot as ambiguous. Do not fall back to another version or choose a processing digest based on sighting order.

For each remaining upsert or explicit delete fact, group repeated sightings by (scoped native_id, operation, revision_sha256). Choose the representative with the earliest normalized receipt commit sequence. Copy the winning member intact, including collector receipt, locators, artifact, processing digest and all authoritative receipt fields. Never blend sightings. A sequence identifies one normalized receipt within its archive. Equal sequence with different receipts is an integrity error. Within that receipt, byte-identical duplicate candidates collapse; unequal representations of the same fact are an integrity error. Apply this independently to each distinct delete fact even for unknown UUIDs. Delete dominance is decided using any eligible deletion, independently of upsert normalizer availability.

Validate the complete eligible candidate set before choosing. Later receipts are excluded before selection and cannot alter an earlier cutoff result. For the same request and exact input coverage/loss policy, any enumeration of the same committed history produces the same snapshot and projection. A new cutoff is a distinct request and changes the snapshot digest even if the selected members are identical. Keep loss reporting tied to selected evidence, except for explicit policy findings such as unsupported projection or missing normalizer; never append observations from post-cutoff receipts. See `representative_cases` in the golden vectors.

Derive the existing `mse.replay/0.1` envelope with `synthetic: true`, observations and tombstones. Reference observation IDs use the unchanged `identifier("observation", subject_id, source_instance, native_id)` on the single fixed source-system/collection scope. Reference rows have the exact `mse.observation/0.1` keys. Copy native ID, subject, source instance, channel, value/unit, event interval and supported epistemic class. Map collector receipt to `received_at` and preserve its meaning in provenance. Set context to unknown. Reference provenance keys are bundle_id, source_name, device_id, calibration_id, method, received_at_semantics, source_revision_sha256 and processing_revision_sha256. Set method to HealthKit SDNN for SDNN and null for HR with unspecified method. Set received_at_semantics to collector_receipt. The quality_flags array is [measurement_error_unqualified, source_availability_unknown]. Preserve snapshot observation order and sort reference tombstones by (observation_id, deleted_at). Recompute the projection and compare to supplied input. Never trust an independently supplied envelope just because a snapshot hash matches.

Map each tombstone to reference observation ID and canonical deleted_at. Deduplicate identical reference pairs only after recording any loss of distinction from rounded time. Keep distinct original facts in the source snapshot. Exclude unknown-derivation HR explicitly. No numerical substitution or reinterpretation. Commit cutoff is enforced upstream. Use a disposable store per snapshot and bind snapshot, projection, bridge/reference/configuration and run digests externally. Results are derived or unavailable and convey no historical online reconstruction.
