## Candidate boundary for a later decision

- **Host and durable artifacts.** Evaluate the established host with a dedicated local filesystem allocation isolated from benchmark activity, existing database paths, NFS source trees and historical QA data. No allocation or artifact path is approved. A sizing check should account for original artifacts, ledger, archive, indexes, WAL, separate backups and restore headroom.
- **Canonical archive.** First rehearse the pinned PF-001 SQLite archive with one writer and explicitly protected original/ledger paths. Compare PostgreSQL after FORGE identifies the required schema, migration and concurrency semantics. A running engine does not resolve which store is canonical.
- **Intake, caller and service identity.** Define one synthetic-only private intake bound to the allowlisted source, TLS identity and an isolated least-privilege writer. No verified endpoint, hostname/certificate binding, intake grant, or MSE-specific service/caller identity was established by this audit.
- **Retention and recovery.** Approve a quota and retention/erasure schedule, dedicated backup destination and custodian, measurable RPO/RTO and a verified coherent restore cut. Keep committed original bytes, the receipt ledger and revision links recoverable together. Maintain inference independence.
