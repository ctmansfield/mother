# Private synthetic archive interface and reproduction inventory

[MSE-EVIDENCE-INFRA-20261121-02 r1](https://github.com/ctmansfield/mother/pull/23#issuecomment-7056096916). ATLAS implementation handoff for FORGE, ORACLE and operator acceptance. The stage authorizes a scoped archive build. The interface below is proposed for the two implementation owners to align. It is independent of the database engine, clone identity and private addresses. Recovery exercise for backup/restore is **DEFERRED by Chad**. Existing offline recovery evidence remains historical.

## Minimal phone write and receipt

| Operation | Request | Result |
| --- | --- | --- |
| Submit or retry | `PUT /v1/archive/batches/{batch_id}` · `Content-Type: application/json` · exact immutable UTF-8 synthetic HealthArchive-compatible capture bytes. No alternate content encoding. Batch ID is the stable bounded token from the frozen 0.2 schema. | `200` for a verified terminal receipt on initial or repeated delivery. `202` only for an actual durable-custody receipt whose authoritative normalization remains pending. |
| Reconcile | `GET /v1/archive/batches/{batch_id}`, with the same grant scope. | `200` or `202` using the same verified receipt semantics. Missing and out-of-scope resources reveal no other scope and return a generic `404` after authentication. |

The v1 server authenticates the private HTTPS caller, derives archive and expected synthetic subject/source scope from its configured grant, and independently reconstructs the trusted deterministic 0.2 export from original bytes before acceptance. For this increment capture kind is `partial`, capture ID equals batch ID within scope, and exporter identity and parser limits are pinned server-side in the reproduction bundle. Clients supply neither normalized rows nor claimed authoritative scope. Restrict this route to the isolated synthetic fixture workflow. A synthetic marker in an arbitrary body would provide no evidence that real records were absent. The phone must feed only generated synthetic fixture bytes, never its active collector archive.

Persist the original bytes, batch ID, SHA-256 and expected scope in the outbox before making any network attempt. No regenerated body, automatic redirect or insecure fallback. Keep the HealthKit anchor and active collector unchanged. Authenticate and verify the configured HTTPS hostname and trust chain. No direct database credentials on the phone. Return `Cache-Control: no-store` on receipt and error responses. Reject unsupported types/encodings, malformed path/body and quota/size violations without advancing progress. Enforce configured byte/record/depth/token limits before authoritative acceptance.

The success body is the frozen `mse.ingest-receipt/0.2` object, including archive ID, four-field scope, batch ID, artifact hash/length, source schema, export digest, receipt ID, custody/commit clocks, sequence, status and PF-001 run binding. Use canonical whole UTC microseconds and lowercase digest encoding defined by the [frozen schema and digest rules](https://github.com/ctmansfield/mother/blob/769a0966da251da4d08633cc7663af9869da70e6/docs/mse/integration/contracts/README.md). The server verifies stored custody and applicable archive linkage before emitting the receipt. The phone checks exact archive/scope/batch/hash/length and schema, valid normalized commitment fields, and status. A `normalized` receipt advances the matching outbox item only. `durably_received` retains pending delivery; retry/reconcile with backoff. A terminal quarantine stops automatic retries, preserves the local original and surfaces bounded status for operator review. Rejection does not advance a checkpoint. Never infer ingestion from HTTP status alone.

Identical scoped retries return the original committed terminal receipt and sequence. Same scoped batch ID with different original bytes or bound export receives `409` with fixed `batch_conflict`, without changing prior commitment. Lost responses and restarts use the stored original batch. Use uniform `401` for absent/invalid grant, scoped denial without identifier echo, `400` invalid request, `413` body limit, `415` unsupported media, and `503` unavailable with no implied acceptance. HTTP transport and exporter versions can change independently only through an explicit compatibility decision; historical receipts stay readable and retryable.

## Authorized operator query and export

The phone grant cannot query/export, browse database tables or retrieve original artifacts. Use separate operator read, controlled export and exact evidence retrieval capabilities. No public exposure, grant forwarding or arbitrary client SQL. When a network operator connects directly to the chosen database, require verified database TLS with hostname/trust validation and constrained read-only roles on versioned views. For an engine without remote DB service, route these same operations through the approved private HTTPS query/export layer. Keep writer, operator and administrator identities separate.

| Logical view | Minimal fields and authorization |
| --- | --- |
| `archive_receipts_v1` | Scoped archive ID, batch/receipt/status, artifact hash/length, committed sequence/time and permitted rejection reason. Filter by authorized archive and source scope and bounded interval or commit range. |
| `archive_revisions_v1` | Scope plus reference to native/source/processing revision, operation, metric, exact decimal and unit where applicable, biological interval, source/collector/commit clocks and quality/exclusion. Resolve a separate scoped cutoff with explicit deletion facts and retain unknowns. Hide raw payload, credentials and filesystem paths. |
| `archive_export_v1` | One approved purpose, scope, interval/cutoff, view version, allowed columns, stable sorting, bounded row/byte size. Ordinary export is UTF-8 JSON with exact decimal strings, explicit unit, clock meaning and coverage. Bind manifest to query/view/version, cutoff, digest and row count. Do not embed keys, raw originals or absolute paths. Original evidence retrieval requires its own requested digest and authorization and verifies reopened bytes separately. |

Keep receipt, original evidence, source/delete revision, supported normalized observation and operator export as separate commitments. Preserve nonpositive metrics as source-only evidence and report PF-001 projection losses per field; do not convert SDNN to another HRV measure. Use stable pagination only if needed within the first size limits. If exposed, bind the cursor to purpose, scope, version, exact cutoff and order; mixed cutoff or scope fails closed. No retained-health export is authorized in this synthetic phase.

The ADR review requires the same input set and bounds across engines, including exact representation, subject/source isolation, immutable batch handling, deletion/late-arrival cutoff, concurrent writer behavior and operator view/export. Source suitability, local benchmark, installed schema and privately verified runtime are separate evidence. Do not infer engine readiness from process availability.

FORGE owns actual engine/DDL/private service and measured ADR. ORACLE owns the durable synthetic producer. PHOENIX is sole runtime and network operator. ATLAS reviews the exact candidate interfaces and reproduction manifest as those pins arrive. No topology, live endpoint, TLS trust material, or engine result has been inferred from this contract.

## SQLite disposition and downstream relational export

PM accepts SQLite for the initial single-writer archive with private HTTPS access only. No remote SQL port belongs in this deployment. FORGE's [matched-workload receipt](https://github.com/ctmansfield/mother/pull/23#issuecomment-7056127886) reports SQLite 3.53.1 and isolated PostgreSQL 16.16 matched 1,025 joined output rows and passed retry, rollback/reopen, cutoff, deletion and competing-writer cases. SQLite reuses accepted PF-001 behavior and minimizes runtime dependencies for this workload. This is a reasonable first engine choice from the receipt. It does not establish remote API concurrency, mount behavior, or production sizing. Review the exact ADR workload, versions and reproduction command when published. The baseline VM decision is separate.

Expose real row-level operator reads through named, versioned and parameterized queries. The contract specifies semantics independent of the eventual route names:

| Operation | Allowed selectors and result |
| --- | --- |
| Receipt lookup/list | Exact batch or receipt ID, or bounded commit range inside the granted archive/scope. Return receipt fields and linkage. No arbitrary predicate or table name. |
| Revision table | Commit cutoff, optional bounded biological interval and metric, and explicit evidence-history or current-at-cutoff mode. Evidence-history includes deletions and retained exclusions. In current mode apply tombstones and eligibility before returning observations; absent or deleted data never becomes zero. |
| Receipt–revision join | Within one authorized scope and cutoff, join a verified normalized receipt and source/processing revision by durable run/member linkage. Return one row per verified receipt/member relation, with key tuple `(archive_id, scope, receipt_id, source_revision_id, processing_revision_id-or-null)`. A repeated source fact can have multiple receipt relations. Preserve that cardinality and provide distinct source/processing IDs for downstream grouping. If a source-only/delete row has no processing revision, retain null and its explicit operation or exclusion. A known tombstone without interval evidence remains visible in scoped deletion/history output. Never join a source revision to a receipt solely by UUID, artifact hash or matching count. |
| Controlled export | Take the same approved filter, profile, and cutoff as the join. Emit deterministic field names/order, exact decimal strings, units and clock semantics, stable scoped relation keys, and canonical UTF-8 JSON. Include schema/view version, row count, cutoff, exact byte digest and scope in an authorized manifest. A consumer can load the permitted projection into another API or a purpose-specific database and verify relation identity and artifact/export linkage. The consumer copy is downstream evidence, with no writeback authority. |

Default profiles should omit raw bytes, native UUIDs when unnecessary, local paths and secret metadata. Use archive-scoped IDs in approved relational projections and treat them as linkable. Any separate purpose narrower than the owning archive grant gets only its own permitted columns, scope and interval. Operator read/export scope is rechecked after a cursor or exact row reference is received. Role tests must deny phone→query, read-only→export, export→raw retrieval, and any cross-scope or cross-purpose ID use. The approved export capability should independently authorize the same bounded query even if the grant cannot access ordinary browsing.

Acceptance requires comparing exact expected identifiers, linkage cardinality, units, decimals, tombstone/exclusion state and cutoff-specific order against reopened authoritative evidence. Include one repeated-source join and one source-only or deletion member; compare the API's joined rows, exported rows and a disposable downstream load using the same provided fixture. Verify forbidden roles cannot fetch associated metadata via joins or export, and enforce row/byte/time limits. Matching counts alone do not prove correctness. The source-only read/join target is independent of optional remote SQL, backup/restore and baseline selection.
