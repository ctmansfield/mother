## Protected catalog

Every admitted member, including directories, is represented in the
member ledger. Files, including empty files and unsupported binary
formats, have exact expanded-byte retrieval by member and digest. SQLite
stores their data in verified 64 KiB chunks and keeps distinct member
links for duplicate payloads. Raw ZIP container bytes remain in original
custody. The source role receives a bounded response under the exact
import, member ordinal and expected digest, never from a source path.

HealthData and selected safe XML/GPX have ordered document events and
indexed preorder elements with parents, physical child positions,
qualified names, namespaces and ordered attributes. Text, mixed content,
comments, declarations and processing instructions remain in protected
storage. Exact expanded member bytes preserve lexical fidelity.
References stay inert. Exact archive-local links resolve to an existing
member ordinal; external, escaping and unresolved references do not
produce network or filesystem access. Parser and integrity refusals
roll back the entire native transaction. Unsupported opaque formats
retain exact byte access.

Top-level records have one primary typed, fallback or quarantine
disposition. Elements and content events have separate denominators.
Initial typed adapters cover exact quantity decimals and units, category
and sleep source codes, workout descriptors, activity dates,
characteristics codes, explicit correlations, BP, and limited descriptors
for some specialized families. Where signal, dose, clinical, vision, or
other family semantics are unqualified, the source representation is
retrievable. An opaque payload or descriptor is not normalized physiology.

It keeps the signed ZIP member allowance and all other admission checks.

The independent guest policy pins the exact transfer manifest and the

activity codes, plus fixed event interval, timeless-record scope and row
limit. Default purposes have no raw member, source-tree or receipt
access. The restricted source role has access only under the admitted
artifact. A full catalog or unrestricted set of records must not be sent
to a model. Verify actual encrypted storage and least privilege on the
target guest before enabling any route.

The guest entry point is `native_universal_guest`. The independently
trusted SHA-256 pins the private admission file and existing operator
provisioning. Initialization creates a fresh database. Serving is a
separate operator action. Mac `native_universal_client preflight` verifies
the exact protected spool and makes no network request. The separate
`execute-manual` mode transfers fixed 512 KiB parts using hostname-verified
mTLS with a writer identity and independently verifies the witnessed
terminal receipt with the receipt identity. `readback` verifies the same
receipt after a lost response. Do not automatically retry refused or
indeterminate outcomes. Keep the exact staged bytes and record sequence
until an authorized reconciliation.

The guest rehashes full member contents and checks integrity links and
structural totals before staging a terminal result. A trusted write-window
observation after synchronous commit is persisted separately as the
publication witness; an unfinished decision stays sealed on reopen.
Neither default purpose nor restricted reads can see staged contents.
No backup/restore, live collector, or Nightscout work is included.
